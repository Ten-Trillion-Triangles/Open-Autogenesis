# Autogenesis

An **AI-driven multiplayer PVP TTRPG/Dynamic Narrative game** built on the [AccelByte Gaming Services](https://accelbyte.io) platform, with three JVM services (`:server`, `:server-extend`, `:matchmaker`) and a Kotlin/JS browser frontend (`:kvisionApp`) that consumes AccelByte SDK bindings generated by Dukat.

The game features AI opponents with distinct personas (including the legendary **Lord Maple Tree**), a Bring-Your-Own-AWS-credentials flow, custom matchmaking optimized for operator margin, and a real-time workstream view of agent reasoning.

## Modules

| Module | Type | Purpose |
|---|---|---|
| `:server` | JVM | Dedicated game server. WebSocket on 9080, gRPC bridge on 9091. Hosts `WorldManager`, `TurnHarness`, `PlayerConnectionManager`. |
| `:server-extend` | JVM | Session router + matchmaker front-end + BYO credential store. REST on 7070, gRPC/gRPC-Web on 9092. |
| `:matchmaker` | JVM | Custom gRPC matchmaker implementing the AccelByte `match2.Service` contract. Listens on 9095. |
| `:kvisionApp` | Kotlin/JS | KVision browser UI. Uses generated AccelByte SDK bindings from `:accelbyteSdk`. |
| `:accelbyteSdk` | Kotlin/JS | Dukat-generated Kotlin/JS bindings for `accelbyte/accelbyte-typescript-sdk`. |
| `:sharedModel` | Kotlin Multiplatform | Common models, RPC bridges, agent defaults — used by all JVMs and JS. |
| `:rpc-ksp` | Kotlin Symbol Processing | Generates RPC bridge code from annotated interfaces. |
| `:electronApp` | JVM orchestrator | Wraps the JS bundle + JVM runtimes + config files into desktop installers. |
| `:electronJukebox` / `:jukebox` | Kotlin/JS | Audio/music tools used by the game UI. |
| `:audioTracksEditor` | Kotlin/JS | Web-based audio editing UI. |
| `:mapEditor` | Kotlin/JS | Web-based map editor. |
| `:grpcBridgeProto` | Node toolchain | Generates Connect/gRPC-Web stubs for the JS bridge. |

See each module's `README.md` for module-specific details.

## Build

Use the Gradle wrapper from the repository root:

```bash
./gradlew :accelbyteSdk:build           # build the AccelByte bindings
./gradlew :accelbyteSdk:check           # run the binding tests
./gradlew :server:build                 # build the dedicated game server
./gradlew :server-extend:build          # build the session router
./gradlew :matchmaker:build             # build the custom matchmaker
./gradlew :kvisionApp:build             # build the browser frontend
```

### Runtime images (custom JRE)

Each JVM module produces a custom-JRE runtime image and portable zip:

```bash
./gradlew :server:runtime
./gradlew :server:runtimeZip
./gradlew :server-extend:runtime
./gradlew :server-extend:runtimeZip
```

## Development Workflow

### One-time setup

1. **Install JDK 24** (or let Gradle's foojay resolver fetch it automatically).
2. **Install Node.js 22.12.0+** — required by the Kotlin/JS Gradle plugin.
3. **Install `protoc`** — required to regenerate the gRPC-Web stubs. See [RUNBOOK §8](RUNBOOK.md#8-grpc-bridge-tooling).
4. **Provision AccelByte** — namespace, OAuth client, match pools, DS Hub. See [RUNBOOK §2](RUNBOOK.md#2-accelbyte-namespace--one-time-setup).
5. **Provision AWS Bedrock** — enable model access in your target regions. See [RUNBOOK §3](RUNBOOK.md#3-aws-bedrock--one-time-setup).
6. **Create `server/accelbyte.local.properties`** and `server-extend/accelbyte.local.properties` with your namespace + OAuth credentials. The root `.gitignore` already excludes `*.local.properties`.

### Day-to-day

```bash
# Run the KVision dev server with hot reload
./gradlew :kvisionApp:jsBrowserDevelopmentRun

# Run with hot reload disabled (for debugging)
./gradlew runKvisionNoHotReload

# Run the dedicated game server
./gradlew :server:run

# Run the session router
./gradlew :server-extend:run
```

For one-click control in IntelliJ IDEA, create three run configurations per [RUNBOOK §"IntelliJ run/debug helper"](RUNBOOK.md).

### Regenerating the AccelByte bindings

```bash
./gradlew :accelbyteSdk:refreshAccelbyteBindings   # full refresh
./gradlew rebuildWithFreshAccelbyteSdk             # clean + full rebuild from scratch
./gradlew ensureAccelbyteSdkRuntime                # ensure SDK artifacts + lockfile are current
```

Override the SDK source with `-PaccelbyteTypescriptSdkRepo=…`, `-PaccelbyteTypescriptSdkBranch=…`, or `-PaccelbyteSdkBuildScript=…`. Pass `-PforceAccelbyteSdkDownload=true` to force a re-clone. For air-gapped builds, set `accelbyteTypescriptSdkMirror=file:///absolute/path/to/clone` in `gradle.properties`.

### Regenerating the gRPC-Web stubs

The Kotlin/JS build regenerates gRPC-Web stubs automatically before `jsProcessResources`. To force a manual regeneration:

```bash
cd grpcBridgeProto
npm install
PROTOC_BIN=/path/to/protoc scripts/generate-grpc-web.sh

# Then refresh the Yarn lock so the frontend picks up the new stubs
./gradlew kotlinUpgradeYarnLock
./gradlew :kvisionApp:browserProductionWebpack
```

## Architecture

```
                   ┌──────────────────────┐
                   │   Browser (kvisionApp│
                   │   KVision + Bootstrap│
                   │   gRPC-Web client)   │
                   └──────────┬───────────┘
                              │  :7070 (REST)
                              │  :9092 (gRPC-Web)
                              ▼
                   ┌──────────────────────┐
                   │   :server-extend     │
                   │   (session router,   │
                   │    BYO cred store,   │
                   │    matchmaker front) │
                   └────┬─────────────┬───┘
                        │             │
                  :9091 │             │ HTTPS to AGS
                  gRPC  │             │ (match2, session,
                        ▼             │  cloudsave, IAM)
             ┌──────────────────┐     │
             │   :server        │     │
             │   (dedicated     │     │
             │    game server,  │     │
             │    WorldManager, │     │
             │    TurnHarness)  │     │
             │   :9080 (WS)     │     │
             └──────────────────┘     │
                                      ▼
                              ┌──────────────────┐
                              │  AccelByte match2│
                              │  → :matchmaker   │
                              │  :9095 (gRPC)    │
                              └──────────────────┘
```

State model: AccelByte CloudSave records + a local VFS under `~/.autogenesis/vfs/`. See [`server/README.md`](server/README.md) for the local-VFS config (`AUTOGEN_VFS_PATH`).

## WebSocket RPC Bridge

The frontend exposes a `WebSocketRpcBridge` alongside the existing REST bridge, so UI components share the same RPC registry while connecting over `/events`. The bridge handles handler registration, player-id generation, automatic reconnects, and exposes the `rpcInvoker` for outgoing calls.

```kotlin
import org.ttt.autogenesis.kvisionapp.WebSocketRpcBridge

WebSocketRpcBridge.registerHandlers {
    register("methodName") { context, params -> "response" }
}
WebSocketRpcBridge.connect("player-id")
val response = WebSocketRpcBridge.rpcInvoker?.invoke("server.method", params)
```

For gRPC transports (browser gRPC-Web, native gRPC), see [`sharedModel/src/jsMain/kotlin/.../GrpcRpcClientJs.kt`](sharedModel) and [`grpcBridgeProto/`](grpcBridgeProto).
