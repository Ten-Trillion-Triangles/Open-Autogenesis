# RUNBOOK — Web Push (VAPID) operations

This is the operator-facing checklist for the turn-start Web Push
pipeline. It expands on `server/README.md` § **Web Push (VAPID)** with
the exact commands, file paths, and approval gates you'll need to run
the pipeline in a fresh environment.

## Pipeline at a glance

```
Browser                                                                                      DS
──────                                                                                      ──
PushNotificationService.subscribeIfPermitted()                              ┐
  → nav.serviceWorker.register("/sw.js")                                    │
  → nav.serviceWorker.ready                                                 │  WS RPC
  → Notification.requestPermission()                                        │   bridge
  → vapid_public.json → pushManager.subscribe({applicationServerKey})       │ (port 9080)
  → subscription.getKey('p256dh'|'auth') (Base64URL)                        │
  → client.registerPushSubscription({endpoint,p256dh,auth})  ──────────────►│
                                                                             ├─► PushSubscriptionStore.put
                                                                             │    VFS userRecord "push-subscription"
[Player disconnects]                                                        │
                                                                             │
[TurnHarness iteration reaches this human actor]                            │
  TurnHarness.executeSingleTurn:1393                                       │
    if (connectionManager has no PRIMARY session for this accelByteId):    │
      launch(IO) { pushNotificationService.sendTurnStart(id, actor, round) }│
                                                                             │
        PushNotificationService.sendTurnStart (server)                      │
          → store.get(id) — returns PushSubscriptionDto                      │
          → effectiveEndpoint = rewriteHost(endpoint, AUTOGENESIS_DEV_PUSH_MOCK_PORT)
          → web-push library: PushService.send(WebPush)
              with VAPID JWT (signed by ~/.autogenesis/vapid_private.pem)
              with ECEH encryption (recipient p256dh, auth)                │
          → HTTPS POST to effectiveEndpoint                                  │
                                                                             │
FAILS → 410 Gone / 404 → store.remove(id)  (dev: Connection refused = mock off)
```

## One-time setup (per environment)

### 1. Provision the VAPID keypair

Pick the deploy host, run as the user that owns `~/.autogenesis`:

```bash
./gradlew :kvisionApp:generateVapidKeys
```

What this does:
- Calls `openssl ecparam -name prime256v1 -genkey -noout` and writes the result
  in SEC1 form to `~/.autogenesis/vapid_private.pem`. Sets 0600.
- Re-derives the public key, strips the SEC1 envelope, Base64URL-encodes
  the raw uncompressed point, and writes
  `kvisionApp/build/generated/vapid/vapid_public.json`.

**The PEM is per-environment. Do not copy it between machines.** A
production deploy host's PEM is independent of dev/CI hosts. A new
deployment must run `generateVapidKeys` on the target machine, and
that machine's KVision bundle must include that machine's
`vapid_public.json`.

### 2. Verify the PEM is PKCS#8

The JVM's `KeyFactory.getInstance("EC").generatePrivate(PKCS8EncodedKeySpec(...))`
expects **PKCS#8 PEM**. The gradle task emits SEC1; the server normalizes on
boot via:

```kotlin
ProcessBuilder("openssl", "pkcs8", "-topk8", "-nocrypt", "-in", pemFile.absolutePath)
```

If you bypass `generateVapidKeys` (manual provisioning, secret-manager
hydration, etc.) and the resulting file is SEC1, the normalization handles
it. If it's PKCS#8 already, the normalization is a no-op pass-through.

You can verify which form you have:

```bash
head -1 ~/.autogenesis/vapid_private.pem
# "-----BEGIN EC PRIVATE KEY-----"     → SEC1 (auto-normalized)
# "-----BEGIN PRIVATE KEY-----"        → PKCS#8 (used as-is)

# Force canonical PKCS#8 explicitly:
openssl pkcs8 -topk8 -nocrypt -in ~/.autogenesis/vapid_private.pem \
  -out ~/.autogenesis/vapid_private.pem
chmod 600 ~/.autogenesis/vapid_private.pem
```

### 3. Verify BouncyCastle loads at boot

The web-push library hard-codes the BC provider name:

```java
nl.martijndwars.webpush.Utils.loadPublicKey(...)  // needs BC
```

`PushVapidConfig.init {}` does this once:

```kotlin
if (Security.getProvider(BouncyCastleProvider.PROVIDER_NAME) == null) {
    Security.addProvider(BouncyCastleProvider())
}
```

The gradle dep `org.bouncycastle:bcprov-jdk18on:1.78.1` is already
declared in `server/build.gradle.kts`. Nothing else is needed; verify
on boot by looking at `~/.autogenesis/logs/server-…log` for either:

- `VAPID keypair not loaded — push notifications disabled (run :kvisionApp:generateVapidKeys to create)` —
  PEM missing or unreadable. Generate or fix permissions.
- `PushVapidConfig: failed to load VAPID keypair at /home/.../vapid_private.pem: <msg>` —
  caught exception. Most often `Unable to decode key` if your PEM is
  malformed. Convert via step 2.

No `VAPID keypair loaded` log line appears on the success path — it
just succeeds silently and `PushNotificationService` is constructed.

### 4. Mount the public key in the KVision bundle

The browser's `serviceWorker.pushManager.subscribe({applicationServerKey})`
reads the public key from `/vapid_public.json` (the live URL the bundle
serves at).

If you're using the production webpack bundle (`build/dist/js/`),
verify:

```bash
grep -c applicationServerKey kvisionApp/build/dist/js/productionExecutable/kvisionApp.js
# Expected: ≥ 1
```

And the served URL returns the public key JSON:

```bash
curl -s http://127.0.0.1:8080/vapid_public.json | jq .
# {"applicationServerKey":"BKQq85e6RXQNE_-4i-Hp6h4BwOn_Nxds299FqGGqavylcjCNADRBlwnkSSoc0u_VizpCsGgytDp4oTWzdTabl74"}
```

If `curl` 404s on `/vapid_public.json`, the static server (`start.mjs`
on :4175 or `kvisionApp-e2e/static-server-8080.mjs` on :8080) is
overlaying the wrong source. The right overlay is
`kvisionApp/build/generated/vapid/vapid_public.json` (artifact of
`generateVapidKeys`).

## Per-environment tweaks

| Knob                                            | Where                                              | Default                                     | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------------- | -------------------------------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AUTOGENESIS_SHUTDOWN_DELAY_MS`                | `.env` / `:server:run` env                         | `60000`                                     | After a single-player WS disconnect, the DS arms a shutdown countdown of this many ms. **For push-notification dev, bump to `600000`** (10 min) so you can reconnect + drive the loop between disconnect and exit. Set to `0` or low for prod — the countdown exists so an idle DS doesn't leak. |
| `AUTOGENESIS_DEV_PUSH_MOCK_PORT`                | `.env` / `:server:run` env                         | unset                                       | When set, every push endpoint has its **host:port** rewritten to `http://127.0.0.1:<port>` at push-send time (path is preserved). Set to `9099` for the local `kvisionApp-e2e/static-server-8080.mjs` listener, or another free port if 9099 is busy. **Leave UNSET in production.** Setting it in prod routes every push to localhost and silently loses them. |
| `AUTOGENESIS_PUSH_TEST_ENDPOINT`                | `.env` / `:server:run` env                         | unset                                       | When set to a non-blank value, forwards to `-Dpush.test.endpoint=true` at JVM startup, mounting the three `/debug/*` push routes (see below). **Leave UNSET in production.** Setting it in prod exposes the seed / advance / trigger routes to anyone who can reach the DS — they can plant subscriptions, complete turns, and force pushes.        |
| `AUTOGENESIS_DEBUG_SHORT_TURN_TIMEOUT_MS`      | JVM `-D…` system property                          | `302000`                                    | Short-circuits the per-turn player-action await to `N` ms, triggering `handleAiTakeover`. Useful only for tests that need fast turn-over. **Set to `3000` for the dev e2e probe** — leave at default in prod. |
| `AUTOGENESIS_DISABLE_AUTO_RESTORE`             | `.env` / `:server:run` env                         | `false`                                     | Disables the WS-rebind auto-restore path. Set `true` for dev — without it the resume-game path runs server-side before the e2e probe's reconnect can fire the resume RPC.                                       |

## The `/debug/*` routes (DEV ONLY, behind `AUTOGENESIS_PUSH_TEST_ENDPOINT`)

| Verb  | Path                               | Purpose                                                                                                                                |
| ----- | ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| POST  | `/debug/seed-push-subscription`    | Body: `PushSubscriptionDto {endpoint, p256dh, auth}` JSON. Query: `userId=<accelbyte-uuid>`. Writes a synthetic push subscription into the VFS. The endpoint host is rewritten by `AUTOGENESIS_DEV_PUSH_MOCK_PORT` at push-send time. |
| POST  | `/debug/advance-turn`              | Query: `player=<name>`. Completes any parked `awaitPlayerAction` for `player` with a synthetic AI-takeover submission. Let the probe skip the 5+ minute real LLM AI-takeover path. |
| POST  | `/debug/trigger-push-now`          | Query: `userId=<uuid>&actor=<name>&round=<int>`. Calls `PushNotificationService.sendTurnStart(userId, actor, round)` directly. Same wire path as the in-game trigger. |

Example run:

```bash
# Seed a subscription for user <test-user-id>:
curl -sX POST 'http://127.0.0.1:9080/debug/seed-push-subscription?userId=<test-user-id>' \
  -H 'content-type: application/json' \
  -d '{"endpoint":"https://example/push/dev-seed/123","p256dh":"BKQq...","auth":"abc..."}'

# Trigger:
curl -sX POST 'http://127.0.0.1:9080/debug/trigger-push-now?userId=<test-user-id>&actor=AUongfa834nfa&round=99'
# → {"status":"delivered","user":"<test-user-id>","round":99}
```

> **Security caveat.** Anyone who can reach the DS on port 9080 can
> POST to these when the env var is set. In dev that's fine; in
> prod it's a footgun. Either remove the env var in prod or block
> `/debug/*` at the reverse-proxy layer.

## Acceptance test recipe (manual)

To prove a fresh environment works without a real LLM turn:

```bash
# 0. Clean VFS
rm -rf ~/.autogenesis/vfs/

# 1. Start the long-lived DS
AUTOGENESIS_SHUTDOWN_DELAY_MS=600000 \
AUTOGENESIS_PUSH_TEST_ENDPOINT=true \
AUTOGENESIS_DEV_PUSH_MOCK_PORT=9099 \
./gradlew :server:run 2>&1 | tee /tmp/srv.log &

# 2. Start the static UI server (Node 22+) or webpack-dev-server (older Node)
node kvisionApp-e2e/static-server-8080.mjs &

# 3. Wait until both ports listen
until nc -z 127.0.0.1 9080 && nc -z 127.0.0.1 8080; do sleep 1; done

# 4. Run the probe (full e2e)
node kvisionApp-e2e/probes/push-turn-start.mjs
# Expected last lines:
#   ==== RESULT: PASS ====
#   mock received first push at <ISO timestamp>
#   method=POST url=/push/dev-seed/<randomN>
#   first push content-encoding: aesgcm
#   first push TTL: 2419200

# 5. Cleanup
pkill -f ':server:run'
pkill -f static-server-8080.mjs
```

If the result is FAIL, see `kvisionApp-e2e/README.md` "Failure modes
the probe is designed to catch".

## Common failure modes and what to check

| Symptom                                                                  | Check                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Browser console: `PushNotificationService: SW registration failed: …`  | `curl http://127.0.0.1:8080/sw.js` — must return 200. If not, the static server isn't overlaying the asset. (See `kvisionApp-e2e/static-server-8080.mjs`.)                                                                                                                                              |
| Browser console: `subscribe failed: Registration failed - permission denied` | Headless Chromium. The `push-turn-start.mjs` probe compensates via `/debug/seed-push-subscription` — see `kvisionApp-e2e/README.md`. **Do not** toggle Chrome flags to "allow". The DTO is the same; only the source changes.                                                                                          |
| Server boot: `PushVapidConfig: failed to load VAPID keypair … Unable to decode key` | `openssl pkcs8 -topk8 -nocrypt -in <sec1> -out ~/.autogenesis/vapid_private.pem` to canonicalize. Re-run the gradle task if you want a fresh key: `./gradlew :kvisionApp:generateVapidKeys`. Verify after restart: `grep 'VAPID' /tmp/srv.log`.                |
| `POST /debug/seed-push-subscription` returns 404                           | `AUTOGENESIS_PUSH_TEST_ENDPOINT` was not forwarded to the JVM. Confirm with `-Dpush.test.endpoint` in the JVM argv: `ps -ef \| grep ServerKt \| grep -o '\\-Dpush\\.test\\.endpoint=[^ ]*'`. Add the env var or pass `-Dpush.test.endpoint=true` on the `:server:run` command line.                                                  |
| Mock receives no POST even though trigger logs "delivered"                 | The VAPID public key in the served bundle doesn't match the private key on the server. The push library signs the JWT with the server's PEM; the receiver verifies it against the `vapid_public.json`. Re-run `:kvisionApp:generateVapidKeys` and rebuild the bundle.                                       |
| `sendTurnStart returned false` with `no subscription for user=…`            | The stored record's `value` is wrapped (`{"value": {...}}`) — the unwrap in `PushSubscriptionStore.get()` is missing. `get()` tries a direct decode first, then unwraps; if both fail it returns null. Confirm the bootstrap order: `generateVapidKeys` regenerates `vapid_public.json`, the static server serves it, the same PEM lives on the DS. |
| AI takeover never completes (loop stuck for hours)                          | Either bump `AUTOGENESIS_DEBUG_SHORT_TURN_TIMEOUT_MS` to e.g. `3000` (3 s) and use `/debug/advance-turn`, or wait 5+ min for the real LLM call. **Don't bump the timeout for prod** — it's bounded by `WorldManager.TURN_TIMEOUT_MS` (300 s default).                                            |
